# ☕ Java-Aprendizado

Repositório dedicado ao estudo e à prática de Java, reunindo exercícios, experimentos, exemplos de implementação e projetos desenvolvidos ao longo da evolução na linguagem.

O objetivo é consolidar conhecimentos de programação por meio da prática, começando pelos fundamentos da lógica e da sintaxe Java e avançando para Programação Orientada a Objetos (POO), princípios SOLID, Design Patterns, estruturas de dados, persistência e desenvolvimento de aplicações com Spring Boot.

Mais do que armazenar códigos de estudo, este repositório funciona como um histórico de aprendizado e referência técnica, permitindo revisar conceitos, comparar diferentes abordagens de implementação e compreender como os fundamentos da linguagem são aplicados em projetos mais estruturados.

---

## 📌 Objetivos do repositório

- Consolidar os fundamentos da linguagem Java por meio de exercícios práticos.
- Desenvolver raciocínio lógico e capacidade de resolução de problemas.
- Compreender os conceitos e pilares da Programação Orientada a Objetos.
- Aplicar boas práticas de desenvolvimento e organização de código.
- Estudar princípios SOLID e sua influência na construção de aplicações manuteníveis.
- Implementar Design Patterns e compreender os problemas que cada padrão resolve.
- Desenvolver APIs REST utilizando Spring Boot.
- Trabalhar com persistência de dados, bancos relacionais e não relacionais.
- Construir projetos que aproximem os estudos de situações encontradas no desenvolvimento de software.

Diretório dedicado à transição da programação estruturada para a modelagem orientada a objetos.

### 9. `Pilares/` — Pilares da Programação Orientada a Objetos

Complementa os estudos de POO, aprofundando os quatro pilares que fundamentam a modelagem orientada a objetos.

**Conceitos estudados:**

- **Encapsulamento:** controle do acesso aos atributos e métodos, protegendo o estado interno dos objetos.
- **Herança:** reutilização e especialização de comportamentos por meio de relacionamentos entre classes.
- **Polimorfismo:** possibilidade de utilizar diferentes implementações por meio de uma mesma abstração.
- **Abstração:** representação das características essenciais de uma entidade, ocultando detalhes desnecessários de implementação.

**Aplicação prática:** construir modelos mais flexíveis, reutilizáveis e organizados, compreendendo como os objetos podem se relacionar e compartilhar comportamentos.

### 10. `SOLID/` — Princípios de design de software

Diretório dedicado ao estudo dos cinco princípios SOLID, utilizados para orientar a construção de aplicações com responsabilidades bem definidas, menor acoplamento e maior facilidade de manutenção.

**Princípios estudados:**

- **SRP — Single Responsibility Principle:** cada classe deve possuir uma responsabilidade bem definida.
- **OCP — Open/Closed Principle:** componentes devem permitir extensão sem exigir alterações constantes em seu código existente.
- **LSP — Liskov Substitution Principle:** implementações derivadas devem poder substituir suas abstrações sem comprometer o comportamento esperado.
- **ISP — Interface Segregation Principle:** interfaces devem ser específicas, evitando obrigar classes a implementar métodos desnecessários.
- **DIP — Dependency Inversion Principle:** módulos devem depender de abstrações, reduzindo o acoplamento entre implementações.

**Organização:**
- `Single_Responsability/`: exercícios relacionados à separação de responsabilidades.
- `ocp/`: práticas de extensão de funcionalidades.
- `lsp/`: exemplos de substituição e herança.
- `isp/`: organização e segregação de interfaces.
- `dip/`: inversão de dependências e utilização de abstrações.
- `Mini_Exemplo/`: exemplos menores para compreensão dos princípios.
- `Exercicio/`: aplicação dos conceitos em problemas práticos.

**Aplicação prática:** identificar problemas de arquitetura, melhorar a organização das classes e desenvolver soluções mais fáceis de testar, modificar e expandir.

### 11. `CreationalPatterns/` — Design Patterns Criacionais

Reúne estudos sobre padrões de projeto criacionais, que abordam diferentes maneiras de instanciar objetos e controlar a criação de dependências.

O objetivo é compreender como desacoplar a criação dos objetos de sua utilização, evitando construções rígidas e facilitando futuras alterações.

**Padrões estudados:**

- **Factory Method:** delega a criação de objetos para métodos especializados, permitindo variar as implementações.
- **Abstract Factory:** fornece uma estrutura para criar famílias de objetos relacionados sem depender de suas classes concretas.
- **Singleton:** controla a existência de uma única instância compartilhada de determinada classe.
- **Prototype:** utiliza objetos existentes como base para criação de novas instâncias.
- **Builder:** separa o processo de construção de objetos complexos, permitindo configurar seus componentes gradualmente.

**Organização:**
- `src/`: implementação dos exemplos e estruturas dos padrões.
- `Problem/`: exploração dos problemas que motivam a utilização dos padrões.

**Aplicação prática:** compreender diferentes estratégias de instanciação e escolher soluções que reduzam o acoplamento e melhorem a flexibilidade do código.

### 12. `StructuralPatterns/` — Design Patterns Estruturais

Diretório voltado aos padrões estruturais, que definem maneiras de organizar classes e objetos para construir estruturas maiores sem comprometer a flexibilidade da aplicação.

**Padrões estudados:**

- **Adapter:** permite integrar interfaces incompatíveis por meio de uma camada de adaptação.
- **Bridge:** separa abstrações de suas implementações, permitindo que evoluam independentemente.
- **Composite:** organiza objetos em estruturas hierárquicas, tratando elementos individuais e agrupamentos de maneira uniforme.
- **Decorator:** adiciona responsabilidades a objetos dinamicamente, sem modificar diretamente suas classes originais.
- **Facade:** disponibiliza uma interface simplificada para acessar funcionalidades de subsistemas complexos.
- **Flyweight:** compartilha informações entre objetos para reduzir o consumo de recursos.
- **Proxy:** fornece um intermediário para controlar o acesso a determinado objeto.

**Organização:**
- `Mini_exemplos/`: implementações menores utilizadas para compreender o funcionamento dos padrões.
- Exemplos e implementações organizados no diretório principal.

**Aplicação prática:** desenvolver estruturas mais modulares, integrar componentes diferentes e organizar relacionamentos entre objetos de maneira mais eficiente.

### 13. `ComportamentalPatterns/` — Design Patterns Comportamentais

Reúne padrões que trabalham a comunicação, a distribuição de responsabilidades e a organização dos comportamentos entre objetos.

O foco é compreender como diferentes componentes podem colaborar sem concentrar toda a lógica em uma única classe.

**Padrões estudados:**

- **Chain of Responsibility:** organiza uma sequência de responsáveis pelo processamento de uma solicitação.
- **Command:** encapsula solicitações como objetos, permitindo separar quem solicita de quem executa uma operação.
- **Iterator:** permite percorrer coleções sem expor diretamente sua estrutura interna.
- **Observer:** estabelece um mecanismo de notificação entre objetos quando determinado estado sofre alterações.
- **Strategy:** permite substituir algoritmos ou comportamentos sem modificar diretamente o componente que os utiliza.

**Organização:**
- `Pratica/`: exercícios voltados à aplicação dos conceitos.
- `src/`: implementação dos padrões comportamentais.

**Aplicação prática:** estruturar fluxos de execução, desacoplar componentes e facilitar a substituição ou evolução de comportamentos dentro de uma aplicação.

## 🚀 Como executar os projetos

### Pré-requisitos

- JDK instalado e configurado.
- IDE de sua preferência, como IntelliJ IDEA ou Visual Studio Code.
- Maven para os projetos que utilizam esse gerenciador de dependências.
- Banco de dados correspondente, quando exigido pelo projeto.

### 1. Clonar o repositório

```bash
git clone https://github.com/arthurresendes/Java-Aprendizado.git
```

Entre no diretório:

```bash
cd Java-Aprendizado
```

### 2. Executar programas Java

Para compilar um arquivo Java independente:

```bash
javac NomeDoArquivo.java
```

Para executar:

```bash
java NomeDoArquivo
```

Caso o arquivo utilize `package`, execute a compilação e a aplicação respeitando a estrutura de diretórios e o pacote declarado.

### 3. Executar projetos Spring Boot

Entre na pasta do projeto desejado e utilize o Maven:

```bash
mvn spring-boot:run
```

Caso o projeto possua Maven Wrapper, também é possível utilizar:

```bash
mvnw.cmd spring-boot:run
```

No Windows, o comando acima deve ser executado no diretório que contém o arquivo `mvnw.cmd`.

As configurações de banco de dados e demais propriedades devem ser verificadas no arquivo `application.properties` ou `application.yml` de cada aplicação.
